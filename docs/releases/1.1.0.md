# One Clipboard History 1.1.0

A new hotkey backend that works in more text-field contexts.

- Add a CGEventTap hotkey backend that intercepts keyboard events at the
  session level. It is selected automatically when the event tap can be
  created, and the app falls back to the existing Carbon `EventHotKey`
  backend otherwise. Settings shows the active backend.
- The CGEventTap backend swallows the matched key press entirely, including
  its auto-repeat, so the focused app receives no stray key combination and
  no longer plays the system alert sound when the shortcut fires.
- Refactor hotkey registration behind the `HotkeyRegistrationAPI` protocol so
  both backends share the same register, suspend and replacement contract.
- Fix the register-replacement contract so replacing an active shortcut
  actually switches the bound combination, and re-enable the event tap when
  macOS auto-disables it after a timeout or user input.
- Detect secure-input contexts (password fields, Keychain dialogs), where
  macOS blocks all global keyboard observation by design, and report the
  shortcut as temporarily unavailable instead of failing silently.

The Carbon backend remains available and is used automatically when the event
tap cannot be created. Existing history data and saved shortcuts remain
compatible.

See the [validation report](https://github.com/armateurlabs/one-clipboard-history/blob/main/docs/VALIDATION.md)
for the checks performed and their limits.
