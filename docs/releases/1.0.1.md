# One Clipboard History 1.0.1

Fix shortcut recovery and interrupted shortcut recording.

- End unfinished recording when settings close, lose key-window status, detach
  the recorder or rebuild its SwiftUI view. Cancellation requests registration
  restoration once, rather than leaving the global shortcut suspended.
- Check that the recorder can receive keyboard input before suspending the
  existing binding; repeated clicks do not start overlapping recording sessions.
- Track the requested preference separately from the current native binding.
  Updating a display label does not register the same physical combination twice.
- Use exclusive Carbon registration so an unavailable combination produces an
  error instead of a silent, ineffective registration.
- Refresh registration after wake and app activation, with bounded recovery.
  Preserve or attempt to restore the previous registered combination on failure;
  report when no binding remains active.

- Keep the screenshot preview from registering a global shortcut that could
  compete with the installed app.

Existing shortcut preferences and clipboard history formats remain compatible.
Regression checks cover registration failures, rollback and recorder lifecycle;
see the [validation report](https://github.com/armateurlabs/one-clipboard-history/blob/main/docs/VALIDATION.md)
for executed checks and the limits of physical-keyboard validation.
