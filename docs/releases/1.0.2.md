# One Clipboard History 1.0.2

Reduce the wait between copying and capture.

- Check clipboard changes every 20 ms instead of 200 ms, with 2 ms timer
  leeway instead of 10 ms. Keep the existing serialized background queue,
  permission checks and complete materialization of all available formats.
- Keep the immediate check when opening history. No keyboard monitoring or
  additional input permission is required for the faster cadence.
- Keep an empty write pending until the source provides its formats, even if
  filling the clipboard does not increment its change count. This prevents an
  early read from making the completed copy disappear from history.
- Extend `--measure` with snapshot, history queue and history update durations,
  without recording clipboard contents or source metadata.

Polling intervals are not delivery guarantees. Slow deferred representations,
large payloads and optional durable persistence can add latency. Copies replaced
between reads can still be missed. Existing history data and shortcut recovery
remain compatible.

See the [validation report](https://github.com/armateurlabs/one-clipboard-history/blob/main/docs/VALIDATION.md)
for measured latency and the limits of the checks.
